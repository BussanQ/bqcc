# DecentID 产品使用说明

> 本文面向使用者，介绍 DecentID 操作台「能做什么、怎么用」，不涉及任何代码或命令细节。
> 如果你需要开发者向的命令行用法，请改看 [`USAGE.md`](./USAGE.md)。

---

## 一、DecentID 是什么

DecentID 是一个**去中心化身份**工具。它帮助你在没有中心服务器、没有平台账号的前提下，拥有一个完全由自己掌控的数字身份，并能：

- 生成一个**稳定、唯一**的身份标识（DID）；
- 用**设备签名**而不是账号密码来证明「我就是我」；
- 给身份附加**公开或加密私有的内容（记忆）**；
- 管理**多台设备**，丢失设备可随时吊销；
- 收发**第三方背书（证明）**；
- 在节点之间**点对点**地交换公开身份状态。

它通过一个**只在你本机运行的网页操作台**来使用——所有操作都在你自己的电脑上完成，私钥不会离开本地。

### 几个直观的类比

| 传统账号体系 | DecentID |
|---|---|
| 在某平台注册账号 | 在本机生成属于自己的身份 |
| 用户名 + 密码登录 | 出示挑战的设备签名 |
| 平台数据库说你是谁 | 你的签名事件链证明你是谁 |
| 换手机要找平台找回 | 自己添加新设备、吊销旧设备 |
| 平台能封禁/注销你 | 没有人能替你撤销身份 |

## 二、先理解几个核心概念

这些概念在界面里反复出现，先花两分钟了解，使用时会顺畅很多。

- **DID（身份标识）**：你的全局身份编号，形如 `did:p2p:....`。它在你第一次创建身份时确定，之后**永远不变**——改名、写内容、甚至更换主控密钥都不会改变它。
- **身份文件**：保存在你本机的一个文件（例如 `alice.json`），里面含有你的身份信息和**私钥**。它是你身份的「钥匙串」，**绝不能发给别人，也不要上传到公开仓库**。
- **公开状态**：从身份文件导出的**不含私钥**的版本，专门给验证方使用。别人用它来核验你的签名，但拿不到你的任何私钥。
- **记忆**：挂在身份下的内容对象，分两种——
  - **公开记忆**：明文，可随身份一起对外发布；
  - **私有记忆**：真正加密保存，默认不会对外发布，只有你本人能解密查看。
- **设备密钥**：用于日常「登录式」签名。可以有多把（手机、笔记本各一把），某把丢了可单独吊销，不影响身份本身。
- **根密钥（root）**：身份的最高控制权密钥，用于管理类操作。可以「旋转」更换，但旋转后 DID 依然不变。
- **证明（Attestation）**：第三方给你的背书（例如「我认识 Alice」）。它是独立对象，你的身份只引用它，不会把它塞进身份文档本体。

## 三、启动与打开界面

把产品构建为可执行程序后，以「操作台」模式启动它。启动后，程序会在窗口里提示一个本机网址（默认 `http://127.0.0.1:8080`）。在浏览器中打开这个网址，即可看到 DecentID 操作台。

几点须知：

- 操作台**只监听本机**，默认拒绝从其它机器访问，也拒绝非 `localhost` 的访问来源。
- 启动时可以指定使用哪个身份文件；若文件还不存在，进入界面后第一步创建身份即可。
- 关闭浏览器不影响身份文件；身份的一切都保存在那个本地文件里。

## 四、界面总览

操作台采用左侧导航 + 右侧工作区的布局。左侧固定有 7 个入口：

| 导航 | 作用 |
|---|---|
| **总览** | 身份概况、快捷入口、密钥清单 |
| **身份** | 创建身份、导出公开状态、查看密钥 |
| **记忆** | 写入公开/私有记忆、解密查看 |
| **设备** | 添加/吊销设备、旋转根密钥、查看密钥时间线 |
| **认证** | 三步完成「挑战 → 签名 → 验证」 |
| **证明** | 签发、验证、附着第三方证明 |
| **网络** | 发布公开状态、从对端解析远端状态 |

左下角始终显示当前使用的**身份文件路径**，并提醒「私钥默认隐藏」。

每个页面顶部有一条**身份概要条**，展示当前 DID（可一键复制）以及事件数 / 设备数 / 证明数三项指标；执行操作后这些指标会自动刷新。

## 五、通用交互方式（每个页面都一样）

DecentID 把所有功能整理成「填表 → 点按钮 → 看结果」的统一节奏：

1. **执行结果面板**：页面底部统一展示结果。
   - 顶部是一条**状态横幅**：成功为绿色、失败为红色；验证类操作还会明确显示「验证通过 / 未通过」。
   - 中间自动列出**关键字段**（如 DID、各类 CID、生成的文件路径、签名密钥等），每项都带一键复制。
   - 底部「原始 JSON」默认折叠，需要细看时可展开。
2. **轻提示（Toast）**：每次操作右上角会弹出一条短提示，告诉你成功或失败原因。
3. **一键复制**：身份概要、密钥、记忆根等处的小图标可直接复制完整值，省去手动选取长字符串。
4. **自动衔接**：上一步的产物会自动填入下一步的输入框，减少手工复制粘贴。典型链路见后文「认证」「记忆」「证明」三节。
5. **危险操作二次确认**：创建覆盖、吊销设备、旋转根密钥、显示私有明文、对外发布等操作，点击后会弹出确认框，确认后才执行。

## 六、分页操作指南

### 1. 身份

**创建本地身份**
1. 进入「身份」页，在「创建身份」卡片填写显示名称与输出文件路径。
2. 点击「创建身份」并确认。系统会生成根 / 设备 / 加密三类密钥，并据此派生出你的 DID。
3. 右侧「当前身份」会显示 DID、根密钥、最新事件等信息。

**导出给验证方的公开状态**
1. 在「公开状态」卡片填写导出文件名（留空使用默认名）。
2. 点击「导出公开状态」。导出的文件**不含任何私钥**，可以放心交给需要核验你的人。
3. 也可点「查看当前公开状态」直接在结果面板预览，不落盘。

> 记住：把**公开状态**给别人，绝不要把**身份文件**给别人。

### 2. 记忆

**写入记忆**
1. 进入「记忆」页，填写类型与内容，选择可见性：
   - **公开**：明文保存，可随发布对外可见；
   - **私有加密**：加密保存，默认不对外发布。
2. 点击「创建记忆」。结果会给出记忆对象与清单的标识（CID），并自动把记忆文件路径填入下方「显示记忆」表单。

**解密/查看记忆**
1. 在「显示记忆」卡片确认记忆文件路径（创建后已自动带入）。
2. 点击「显示明文」并确认。公开记忆直接显示；私有记忆会**临时解密**后显示，且页面已设置不被浏览器缓存。

右侧面板始终显示当前的**公开记忆根**与**私有记忆根**，均可一键复制。

### 3. 设备

**添加设备**：填写设备标签（如 laptop / phone），点击「添加设备」。新设备的密钥编号会自动填入下方「吊销设备」表单，方便你核对。

**吊销设备**：当某台设备丢失或不可信时，填入它的密钥编号与原因，点击「吊销设备」并确认。**被吊销的设备将无法再用于签名**，但你的身份和 DID 不受影响。

**旋转根密钥**：当你想更换最高控制权密钥时，填写新根标签并确认。旋转后控制权交接给新根密钥，而**DID 保持不变**，历史记录依然可被验证。

右侧「密钥时间线」按时间展示所有密钥的加入与吊销情况，已吊销的会以红点和说明标出。

### 4. 认证（核心：证明「我是我」）

这是一个**三步向导**，从左到右依次完成，且每一步的产物会自动带到下一步：

1. **创建挑战**：验证方填入要核验的 DID 与有效期，点击生成。挑战包含随机数与过期时间，不在服务端留任何账号状态。生成后会自动填入第 2 步。
2. **本地签名响应**：身份持有者用有效的设备密钥对挑战签名（默认用首选设备，也可指定某把设备）。签名结果会自动填入第 3 步。
3. **使用公开状态验证**：验证方贴入持有者的**公开状态**与上一步的**响应**，点击验证。你也可以点「填入本地公开状态」一键带入本机身份的公开状态做自测。

结果会明确告诉你**是否通过**。过期的挑战、被吊销设备的签名都会被判为不通过。

> 整个过程不依赖任何中心账号系统，验证方只需要你的**公开状态**，不需要、也拿不到你的私钥。

### 5. 证明

**签发证明（作为背书方）**：填写被背书者的 DID、声明类型与内容、有效期等，点击「签发证明」。证明是独立对象；签发后会自动填入下方「验证」与右侧「附着」两个表单。

**验证证明（作为验证方）**：贴入背书方的公开状态与证明内容，点击「验证证明」。系统会核验签名与有效期。

**附着证明（作为被背书者）**：把收到的证明贴入右侧卡片并确认，系统会以「引用编号」的方式把它挂到你的身份下，而不会把证明内容塞进身份文档本体。

### 6. 网络

**发布公开状态**：填写监听地址与服务时长，选择是否同时发布已附着的证明，点击「立即发布」并确认。程序会临时上线，对外提供你的**签名身份状态、公开记忆**以及（可选）**已附着证明**。**私有记忆永远不会被发布。**

**从对端解析**：填入对方的网络地址与要查询的 DID，点击「解析状态」。取回的状态会先经过完整校验，确认无误后再展示。

右侧面板列出了本页对外只会传输哪些内容，并明确标注「私有记忆已排除」。

## 七、安全与隐私边界

- **私钥不出本机**：身份文件中的私钥默认不会出现在界面或接口返回里；界面只展示公开密钥与「是否本地持有」。
- **私有记忆是真加密**：私有记忆以密文保存，只有你本人能解密；发布时默认排除。
- **只听本机**：操作台默认拒绝非本机来源与非 `localhost` 访问。
- **明文显示需手动触发**：私有记忆明文只有在你点击「显示」并确认后才会出现，且不被缓存。
- **对外只发布该发布的**：发布动作只对外暴露签名身份状态、公开记忆和可选的已附着证明。

仍需你自己注意：

- **不要外发身份文件**，也不要提交到公开仓库；要给验证方的是**公开状态**。
- 当前为原型阶段，身份文件中的私钥仍以本地明文形式保存，请妥善保管所在电脑与文件。

## 八、常见问题（FAQ）

**Q：改了显示名称 / 写了新记忆 / 换了根密钥，DID 会变吗？**
不会。DID 只在首次创建时确定，之后永久不变。

**Q：我换了新手机怎么办？**
在「设备」页给新手机添加一把设备密钥即可；旧手机若丢失，用「吊销设备」停用它。身份本身不受影响。

**Q：验证方需要我的什么？会拿到我的私钥吗？**
只需要你的**公开状态**。它不含任何私钥，验证方无法据此冒充你。

**Q：私有记忆别人能看到吗？**
不能。它是加密保存的，默认不对外发布，且只有你本人能解密。

**Q：身份文件能不能给同事/客服？**
不能。身份文件里有私钥，等同于把身份完全交出去。任何需要核验你的人，给他**公开状态**就够了。

**Q：没有中心服务器，谁来保证身份的真实性？**
由你的**签名事件链**保证：每一次变更都有当时有效密钥的签名，验证方通过逐条回放即可确认真伪，不依赖任何平台数据库。

## 九、名词速查

| 名词 | 含义 |
|---|---|
| DID | 你的全局身份标识，永久不变 |
| 身份文件 | 含私钥的本地钥匙串，**不可外发** |
| 公开状态 | 不含私钥、给验证方核验用的版本 |
| 记忆 | 挂在身份下的内容（公开明文 / 私有加密） |
| 记忆根 | 当前公开/私有记忆集合的标识 |
| 设备密钥 | 日常签名用的密钥，可多把、可单独吊销 |
| 根密钥 | 最高控制权密钥，可旋转更换 |
| 挑战 / 响应 | 「出题—签名作答」的登录式验证流程 |
| 证明 | 第三方对你的背书，独立对象、以引用附着 |
| CID | 内容寻址标识，用来指向某个具体对象/清单 |
| 发布 / 解析 | 点对点地对外提供 / 从对端取回公开状态 |
