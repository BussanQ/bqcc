# DecentID 产品使用说明

> DecentID 的核心只有 3 件事：**身份是一把密钥，历史是一条签名链，登录是一次签名。**
> 第一次使用前建议先读两分钟的 [`概念模型.md`](./概念模型.md)。命令行用户请看 [`USAGE.md`](./USAGE.md)。

## 一、启动操作台

构建程序后，以本机 Web 模式启动：

```bash
decentid web -identity identity.json -addr 127.0.0.1:8080
```

浏览器打开 `http://127.0.0.1:8080`。操作台默认只接受本机访问；身份文件是包含私钥的**钥匙串**，绝不能发给别人或提交到公开仓库。

界面分两层：

- `/`：默认简单模式，按真实任务分为「我 / 验证 / 内容 / 设备 / 备份」。
- `/advanced`：高级协议控制台，面向需要 DID、CID、JSON、网络地址和完整 challenge-response 流程的开发者。

## 二、默认简单模式

### 1. 我：创建并查看身份

首次打开时，填写一个展示名称并创建身份。系统会生成主控、设备和加密密钥，并由首次主控公钥算出永久不变的**身份码**：

```text
did:p2p:<hash(initialRootPublicKey)>
```

创建完成后可复制或用二维码出示身份码。展示名称不是身份码的一部分；写内容、撤销设备或轮换主控密钥都不会改变身份码。

> 创建已有路径会被拒绝，避免意外覆盖钥匙串。确实要替换身份时，请先做好完整备份，再使用 CLI 的显式 `-force`。

### 2. 验证：本机签名自检

“本机签名自检”会在当前电脑上执行一次完整的：

1. 生成随机题目；
2. 用当前设备密钥签名；
3. 用公开名片重算身份并验签。

它用于检查“这台设备的密钥是否可用”，不表示已经向第三方完成登录，也不证明现实世界中的唯一身份。

需要让别人验证时：

- 把**公开名片**交给对方；它不含私钥。
- 真正登录仍是“对方出题 → 你用设备密钥签名 → 对方用公开名片验签”。
- 永远不要把本地 identity 文件交给验证方。

### 3. 内容：公开或只有我能看

写内容时可选择：

- **公开**：明文保存，可随身份点对点发布。
- **只有我能看**：使用 X25519 + AES-GCM 加密保存，默认不发布；点击“查看”时才在本机解密。

内容目录是一个不可变的累积快照。每次新增内容都会生成新的目录，并通过一条签名变更记录更新当前根；简单模式列表、完整备份和 P2P 发布都以当前目录为准。

旧版本曾把每条内容写成独立单项目录。如果页面提示“发现旧版本地内容”，可点“纳入当前内容目录”：

- 只纳入 CID 正确且能由当前身份历史主控公钥验证的对象；
- 只追加新的签名变更记录；
- 不修改身份码、旧内容 CID 或既有历史；
- 未整理前，完整备份会明确拒绝，避免静默漏掉内容。

### 4. 设备：管理本地设备密钥

当前简单模式的“新增本地设备密钥”是在**当前钥匙串**中生成另一把签名密钥：

- 可为不同用途保留多把设备密钥；
- 某把不可信时可单独撤销；
- 撤销后不能再用于新的登录签名，但历史验证和身份码不受影响。

这不是跨设备配对：密钥不会自动发送到另一台手机或电脑。真正的跨设备密钥生成、授权和传输尚未实现。

### 5. 备份：完整加密恢复

导出的 v2 完整备份包含：

- 本地钥匙串；
- 当前公开/私有内容目录和内容对象；
- 已附着的 standalone 他人背书对象。

私有内容本身仍是密文；整个 bundle 还会使用 scrypt 派生密钥和 AES-256-GCM 再加密。恢复时会先校验身份回放、对象 CID 和引用完整性，再写入对象并最后替换 identity 文件。

旧版 v1“仅身份”备份仍可导入，但恢复后会显示警告：它不包含内容或他人背书，缺失的私有内容也无法从网络找回。

## 三、高级控制台

`/advanced` 保留完整协议操作：

- **身份**：创建身份、查看/导出公开名片和安全密钥摘要。
- **内容**：创建公开/私有 memory，显式解密查看。
- **设备**：新增/撤销设备密钥、轮换主控密钥。
- **认证**：challenge → respond → 使用公开名片 verify。
- **他人背书**：签发、使用 issuer 公开名片验证、以 CID 附着。
- **网络**：临时发布公开状态/内容、从指定对端取回并验证状态。

高级模式不会放宽安全边界：API 默认不返回私钥，private memory 不发布，远端状态必须通过 replay 验证。

## 四、安全边界

- **identity 文件是钥匙串**：包含私钥，只保存在受信任的本机。
- **公开名片可分享**：只包含文档和签名变更链，不包含 `localKeys`。
- **私有内容是真加密**：对象文件中没有明文 payload，P2P 发布集合明确排除 private manifest/object。
- **他人背书是独立对象**：身份只记录 CID 引用，不把背书内容嵌进身份文档。
- **备份口令无法找回**：口令丢失就无法解密备份；不要把口令与备份放在同一位置。
- **当前仍是原型**：本地钥匙串中的私钥尚未接入系统钥匙串、硬件密钥或生产级保护。

## 五、常见问题

**写内容或轮换主控密钥后，身份码会变吗？**
不会。身份码只来自首次主控公钥。

**“本机签名自检”是否等于已经登录某个网站？**
不是。它只检查本地能力；外部登录必须由验证方提供题目并验证你的签名。

**新增本地设备密钥后，手机就能使用吗？**
不能。当前操作只在同一个钥匙串中新增密钥，不会完成跨设备传输。

**别人能看到私有内容吗？**
默认不能。私有对象是密文，发布流程也会排除它们。

**给验证方什么文件？**
给公开名片，例如 `identity-state.json`；绝不要给 `identity.json`。

**为什么备份前要求整理旧内容？**
为了让“当前内容列表、身份内容根、P2P 发布和备份”指向同一集合，避免看似备份成功但实际遗漏旧文件。
